# Humanization behavior

`HumanInteractionOptions.CompatibilityMode` is opt-in. Its default remains `Legacy`, preserving the existing humanizer dispatch. Mouse trajectories remain Bézier by default; `MouseAlgorithm = MouseTrajectoryAlgorithm.Cursory` explicitly selects the experimental native adapter.

## PlaywrightCompatible

In this mode, parameterless locator/page/frame Fill and Clear, locator Press, InsertText, mouse Wheel, and other calls not explicitly supported are delegated to the original Playwright implementation. Calls supplying options are deliberately raw as well; no options object is inspected or changed. This retains Playwright's actionability, strictness, errors, event semantics, and native support for input types/contenteditable.

Parameterless locator Click, DblClick and Hover do a Playwright trial first, optionally prepare pointer movement toward the current target center, then invoke the native locator action exactly once. Preparatory movement is additional pointer activity, not a promise that every event matches an unwrapped call. If no usable bounding box is available, the native action remains the final operation. The final Playwright operation re-resolves and validates the target, so movement does not authorize clicking a stale rectangle. Click options (Force, Trial, Position, modifiers, button, timeout, etc.) remain raw.

Explicit Type/PressSequentially and keyboard Type are paced only when each text element contains one Unicode scalar. If the string contains a multi-scalar grapheme (such as a combining sequence, joined emoji or flag), or malformed UTF-16, the complete original call is delegated before any paced prefix is sent. The SDK does not claim universal IME/composition support. A total `TypingDeadlineMilliseconds` budget (default 30 seconds) limits pauses and further characters; cancellation and page closure are checked between characters. SDK-owned stages derive their remaining timeout from the page's monotonic input-operation lease, including time spent queued and observed default timeouts, rather than starting a fresh full budget for focus/readiness/final action. Native timeout adjustments clone supplied options and preserve explicit timeout values, including native-unlimited `Timeout=0`. A command already in-flight in Playwright cannot be forcibly cancelled by this SDK. Use raw Playwright (or `Humanize=false`) when exact input events or IME behavior matter. Fill and InsertText are not converted to paced typing. Press chords stay native.

## Wrapper contract matrix (tickets 11–14)

The configured `Browser` adapter routes both `Browser.NewContextAsync`/`NewPageAsync` and the handle factories through one raw-browser factory. The raw browser is intentionally an escape hatch: `RawBrowser` factories bypass identity defaults, runtime preparation, wrapper decoration, and configured-context publication. The adapter does not retroactively prepare contexts created through that bypass. `Humanize=false` disables decoration only; configured identity settings still apply through the configured factories.

Context/page options are shallow-cloned before defaults and callbacks run. For identity fields (locale, timezone, viewport/screen, device scale, user agent), precedence is: identity default where the caller left a value unset; explicitly supplied factory options override those defaults; `ConfigureContext`/`ConfigurePage` run last and can override either. Non-identity fields on caller options are retained. `DefaultTimeoutMilliseconds` and `DefaultNavigationTimeoutMilliseconds` are applied to each successfully prepared context at runtime; they are not properties of `BrowserNewContextOptions`/`BrowserNewPageOptions` and therefore cannot be overridden by those option objects or by the option callbacks. A later explicit Playwright `SetDefaultTimeout`/`SetDefaultNavigationTimeout` call is the caller's override; for action timeouts, an explicit page default takes precedence over the context default, including when either default is updated later. Factory callbacks execute before the raw resource is created; if one throws, its original exception propagates and no context is published.

Configured browser `Context` events announce only factory-created contexts, after preparation; sender is the configured browser adapter and event args are the same public context returned by the factory/listing. Browser/context/page collections are snapshots, not mutable internal registries. Context close removes registration. Supported page/context events forward known Playwright payloads through the same wrapper cache; arbitrary user payloads and unrecognized events are not recursively transformed. Callbacks run outside registration locks. Repeated add/remove follows .NET's last-registration removal behavior; disposing the handle detaches SDK-owned bridges and is idempotent. RpaBlockly's existing adapter remains a separate integration boundary and is not replaced by these SDK contracts.

Frame and locator wrappers propagate page ownership and cache identity through `IFrameLocator`, `IFrame`, locator collections (`AllAsync`), and direct known Playwright-valued method arguments. Known locator `Has`/`HasNot` values in the explicitly supported locator option DTOs are unwrapped through a shallow clone when needed, leaving the caller's options unchanged. This is a targeted Playwright argument adaptation, not recursive rewriting of arbitrary nested option values; `Wrapped_known_playwright_locator_argument_inside_options_is_unwrapped` tests that boundary. The generic dispatcher does not recursively rewrite arbitrary DTOs, `Evaluate` values, or unrelated results; only declared Playwright interfaces and supported collections are decorated. `Wrap(Wrap(x))` is idempotent and `Unwrap(Wrap(x))` returns the raw object. Cache ownership uses `ConditionalWeakTable`; the browser contract matrix includes bounded real weak-reference/GC assertions after raw and wrapped disposable contexts/pages close. Collection runs on a fresh worker stack so a completed Playwright close continuation on the test stack does not create a false retention result. The heap-root investigation and focused passing execution are documented in `implementation/wrapper-retention-root-analysis.md`; this is not proof that arbitrary application-held wrappers are collectible. Weak storage prevents the cache itself from pinning its keys, but application-held wrappers/pages remain strongly reachable by design. Cross-origin local-frame behavior is verified with loopback origins; diagnostics assertions, rather than DOM success alone, are needed to prove the humanized interaction route ran.

Decoration is not a promise that every Playwright method is humanized. Supported human-paced interaction routes are the explicitly handled locator/page/frame `ClickAsync`, `DblClickAsync`, `HoverAsync`, `FillAsync`, `ClearAsync`, `TypeAsync`/`PressSequentiallyAsync`, keyboard `TypeAsync`/`PressAsync`, and mouse movement/button/wheel methods according to the selected compatibility mode. Methods such as element-handle `ClickAsync`/`FillAsync`/`TypeAsync`, drag/drop, check/uncheck, select-option, file input, arbitrary keyboard methods, and unlisted APIs are forwarding-only unless a specific route is added and tested; forwarding preserves Playwright availability but carries no humanization guarantee. For exact unsupported-method behavior use the native Playwright API via the wrapper or `Unwrap`.

## Trajectory ownership

`HumanActions` owns random state and per-page cursor knowledge through weak page tables; trajectory data is shared by the pure Cursory library, while each generation uses isolated random state. The internal Bézier seam remains unchanged and selected by default. Cursory is an experimental opt-in adapter over `SpyBrowser.Cursory`, not a copied algorithm or plugin API.

Cursory sampling frequency and directness are passed to the pure generator. The adapter only scales its returned timestamps to `MouseMinimumDurationMilliseconds`/`MouseMaximumDurationMilliseconds`; it does not regenerate the selected recording. The scheduler uses monotonic absolute times, awaits each native call serially, skips overdue intermediate samples, and observes a bounded `CursoryMovementDeadlineMilliseconds`. It may not meet planned timing under transport or browser load, and deadline/page-close/fault can stop before the endpoint.

Pointer position is page-specific and is recorded only after a confirmed send. The adapter does not quantize generated CSS coordinates, but the local Chromium/Playwright browser test currently observes integer `MouseEvent.clientX/clientY` even for fractional inputs and DPR 1, 1.25, 1.5, and 2; this is a browser/driver observation, not evidence that all browsers round identically. Since Playwright cannot query the physical cursor position, an unknown Cursory position sends just the requested endpoint as a bootstrap anchor; subsequent moves can generate a path. Wrapped raw `Mouse.MoveAsync` (including calls with options) and successful coordinate-bearing `Mouse.ClickAsync`/`DblClickAsync` update the observation from their successfully sent endpoint. A failed raw move/click invalidates position because protocol failure does not prove that no partial movement occurred. Raw locator/page/frame click, hover, check and drag-style actions conservatively invalidate position because Playwright may reposition while resolving the native action. Their failure also leaves the position unknown. Wrapped `DownAsync`/`UpAsync` tracks observed button state; a button transition whose raw call fails is treated as uncertain until a successful owner-side Up is observed. While a button is known down (or uncertain), compatible locator actions do not prepare a separate pointer move or release the button; Playwright still receives its single native semantic action. Calls through `PlaywrightHumanizer.Unwrap` cannot be observed: after external raw input, call `humanizer.InvalidateMousePosition(page)` before the next humanized move. This invalidation intentionally clears position knowledge, not button ownership. An unwrapped external `Mouse.DownAsync`/`UpAsync` is equally unobservable; Playwright exposes no reliable API here to query which buttons another caller currently owns. Do not infer that state from cursor invalidation, and never issue a blanket release to “clean up” unknown button state. Conservative unknown position may skip humanized preparation; this is safer than generating a trajectory from an invented origin. If external button ownership may be active, keep that interaction on the raw Playwright route until its owner explicitly resolves it.

The Cursory native library is a preview whose upstream parity and dataset redistribution review remain separate gates. Selecting it explicitly should be limited to local evaluation until those gates pass. No additional trajectory-generation process is launched; Playwright's normal driver remains part of the ordinary Playwright runtime.

## Verification

Run `dotnet test tests/SpyBrowser.Tests/SpyBrowser.Tests.csproj`. Browser motion tests use `BrowserFact`/`BrowserTheory` and are skipped unless `SPYBROWSER_RUN_BROWSER_TESTS=1`; provision the repo's Playwright Chromium if enabled. Report skips separately: unit tests alone do not establish browser coverage. A reproducible motion benchmark is provided at `tools/native-motion-benchmark`; record its machine/runtime/browser output rather than treating timings as a CI performance guarantee.
