# GitHub release dispatch recovery

## Incident

Release run `37444172501` for `v0.2.0-beta.2.1` checked out the corresponding frozen source commit `7983680083dd66aea2ff39a753533d02d8de2491` and passed the pinned SDK (`8.0.319`), build, and distribution gate. Testing then failed: `SPYBROWSER_RUN_BROWSER_TESTS` was absent, while `ContextEventContractsTests` deliberately assert that it equals `1`. The recorded failures therefore reported expected `"1"`, actual `null`; they are not grounds to weaken or skip those assertions. The workflow also had not installed Playwright browsers. The full failure record remains at `artifacts/goal/resumed-e09/release-beta21-failure.log`. This run published no beta.2.1 release assets.

## Workflow-only recovery

`.github/workflows/release.yml` now installs Chromium and its system dependencies using the `playwright.ps1` generated by the built `SpyBrowser.Tests` project, explicitly runs tests with `SPYBROWSER_RUN_BROWSER_TESTS=1`, and records TRX output at `artifacts/test-results/release-tests.trx`. Tests remain a prerequisite for packaging and release asset publication. Existing source checks, timeouts, legal/publication gate, and separate NuGet and GitHub Packages opt-ins are retained. Browser execution remains headless by default; there is no headed CI lane, so headed coverage is explicitly not claimed.

The required `workflow_dispatch` `tag` input supports rerunning the fixed workflow from current main against an existing release tag. Push releases still select their pushed tag. In either case the effective tag is passed to checkout without shell interpolation; validation requires the `v`-prefixed declared package version, a full checked-out commit SHA, and the tag's commit to equal `HEAD`. Release creation uses that same tag and `gh release create --verify-tag`. This does not move or overwrite tags or assets; no `--clobber` is used. The existing immutable `v0.2.0-beta.2.1` tag is not rewritten, and the failed run published no beta.2.1 assets. GitHub release assets require no registry credential; registry publication routes remain independently gated.

No production source, version, tag, package feed, or failed-run evidence was changed as part of this recovery.
